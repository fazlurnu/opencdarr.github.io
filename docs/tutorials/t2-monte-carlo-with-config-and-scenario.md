# T2. Using built-in estimator

In T1 we learned how to write our own performance and kinematics models, and how to fly an encounter
with them. At the end we estimated the probability of a loss of separation, `P(LoS)`, by sampling the
same encounter many times under different seeds. That sampling is the routine way to get the
probability of an event out of a Monte Carlo simulation, so the library has a built-in function for
it, `estimate_p_los`. First, though, we set up the user-defined performance and kinematics again.

## T2.1. Your components

Unchanged from T1.

```python
from opencdarr import Performance, Kinematics
from opencdarr import AircraftState, MotionCommand
from opencdarr import WindField, NO_WIND
from dataclasses import replace

RPZ = 50.0     # protected-zone radius [m]
DT = 0.5       # integration step [s]
G = 9.80665    # standard gravity [m/s2]

MY_FIXEDWING = Performance(
    v_max=24.0, v_min=13.0, ax=1.8, yaw_rate_max=0.0, phi_max=40.0, roll_rate_max=60.0,
)


class SimpleFixedWing(Kinematics):
    """A bank-limited point mass, commanded in ground velocity. Ignores the wind."""

    def validate_performance(self, perf: Performance) -> None:
        bad: list[str] = []
        if perf.v_min <= 0.0:
            bad.append("v_min is a stall speed here and must be > 0")
        if perf.phi_max <= 0.0:
            bad.append("phi_max must be > 0 (this model turns by banking)")
        if bad:
            raise ValueError(
                "SimpleFixedWing was given an envelope it cannot fly: " + "; ".join(bad)
                + ". Pass a fixed-wing Performance such as MY_FIXEDWING."
            )

    def step(
        self,
        state: AircraftState,
        command: MotionCommand,
        perf: Performance,
        dt: float,
        wind: WindField = NO_WIND,
    ) -> AircraftState:
        """Advance one timestep. `wind` is accepted and deliberately not read (see L1.7)."""
        v_cmd = min(max(command.gs, perf.v_min), perf.v_max)
        v = state.gs + min(max(v_cmd - state.gs, -perf.ax * dt), perf.ax * dt)

        omega_max = math.degrees(G * math.tan(math.radians(perf.phi_max)) / max(v, 1e-9))
        error = ((command.trk - state.trk + 180.0) % 360.0) - 180.0
        trk = (state.trk + min(max(error, -omega_max * dt), omega_max * dt)) % 360.0

        lat, lon = geo.forward(state.lat, state.lon, trk, v * dt)
        return replace(state, lat=lat, lon=lon, trk=trk, gs=v, yaw=trk)
```

## T2.2. The config, and the scenario

In T1 we passed a number for every setting, one argument at a time. Often we would rather keep those
numbers in a file outside the simulation and use them as a baseline, and that is what the `Config`
class is for. Below we build one in Python rather than loading it from a config file.

```python
from opencdarr import Config
from opencdarr.config import AircraftUncertaintyConfig, ConflictConfig, SimulationConfig

CONFIG = Config(
    seed=0,
    aircraft_uncertainty=AircraftUncertaintyConfig(
        pos_ci95=60.0,   # m — 95 % radial position accuracy
        vel_ci95=3.0,    # m/s
    ),
    conflict=ConflictConfig(rpz=RPZ, t_lookahead=120.0),
    simulation=SimulationConfig(dt=DT, t_max=600.0, done_timeout=10.0,
                                broadcast_interval=1.0),
)
CONFIG
```

```{ .text .output }
Config  seed 0
  uncertainty  sensor  pos 60 m, vel 3 m/s (95% radial)
  conflict    rpz 50 m | lookahead 120 s
  simulation  dt 0.5 s | broadcast every 1 s (fixed gaps)
              ends on 10 s clear, 600 s cap
```

The other difference from T1 is how the encounter itself is defined. Previously we created the
conflict with `create_conflict`. The `Scenario` classes generalise that, and they cover cases such as
`PairwiseEncounter`, `CrossingRing` and `RandomTraffic`. Only `PairwiseEncounter` is shown here; the
other two come later.

```python
from opencdarr import Airframe
from opencdarr import M600, Multirotor
from opencdarr.scenario import PairwiseEncounter

airframes = [Airframe(M600, Multirotor()),
             Airframe(MY_FIXEDWING, SimpleFixedWing())]

ENCOUNTER = PairwiseEncounter(
    speed=16.0,     # m/s — ownship cruise
    gs_intr=18.0,   # m/s — intruder cruise, inside MY_FIXEDWING's envelope
    dpsi=45.0,      # deg — crossing angle
    dcpa=0.0,       # m — miss distance
    dcpa_max=50.0, tlos=60.0,
)
```

Note that unlike `Agent`, an `Airframe` is only a combination of `performance` and `kinematics`, with
no `AircraftState`. The position and velocity of the `AircraftState` are generated by the scenario,
and the sensor and navigation accuracies come from the `Config`. To see the agents that result, we do:

```python
ENCOUNTER.agents(CONFIG, airframes)
```

`CONFIG` has to be passed here because we will want to override some of its values later, when we run
an `experiment`. An experiment is this same Monte Carlo simulation repeated under a set of different
conditions.

## T2.3. Run it

The last part is to run it. Unlike T1, the Monte Carlo loop is handled by `estimate_p_los`, and it
can run in parallel through `joblib`. Set `n_jobs` to the number of CPU cores to use, where
`n_jobs=-1` means all of them.

```python
import math
import time

from opencdarr import geo
from opencdarr import estimate_p_los
from opencdarr import StateBased, MVP, PastCPA
from opencdarr import GnssNavigation, Comm, LastKnown

from opencdarr.cns import lognormal_latency

t0 = time.perf_counter()

est = estimate_p_los(
    ENCOUNTER.builder(airframes),
    CONFIG,
    detector=StateBased(), resolver=MVP(margin=1.05), recovery=PastCPA(),
    navigation=GnssNavigation(),
    communication=Comm(reception_prob=0.7,                         # every link, both directions
                       latency=lognormal_latency(median=0.5, sigma=0.6)),
    surveillance=LastKnown(),
    n_encounters=3000,
    n_jobs=-1,       # every core; the encounter fan-out is sliced
)

print(est)
print(f"Done in {time.perf_counter() - t0:.1f} s")
```

```{ .text .output }
MonteCarloEstimate  52 losses in 3000 encounters
  p_los      0.0173333 (per run, per aircraft and mean K coincide)
  closest    median 170.6 m (per-encounter record: min_seps)
  detection  rate 1 (a diagnostic, not the result)
Done in 5.3 s
```

Voilà! The same encounter, and less time spent on the same number of runs, because the loop ran in parallel. The `P(LoS)` estimate differs slightly from T1's because `estimate_p_los` spawns its random streams in a different tree.
