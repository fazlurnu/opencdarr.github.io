# Rare-event simulation: the short theory

A collision is supposed to be rare — which is exactly what makes it hard to measure. If loss of separation happens once in a million encounters, plain Monte Carlo needs on the order of a million runs to see even one, and a batch that reads *zero* events says nothing about whether the true rate is $10^{-6}$ or $10^{-9}$. At the [safety targets that matter](../index.md#the-problem), around $10^{-9}$ per flight hour, brute-force sampling is not just slow but unreliable.

OpenCDaRR's answer is a **rare-event estimator** built on the [`ips`](https://github.com/fazlurnu/OpenCDaRR/blob/main/opencdarr/ips.py) module — the fixed-effort **interacting particle system** (IPS) of Blom et al. (2007), also called multi-level splitting. Instead of waiting for the rare event to happen on its own, it concentrates a fixed population of particles on the trajectories already heading for it, and returns the small probability with a confidence interval.

This page covers the method; see [Running a simulation](running.md) to run it, [Validation](validation.md) for the evidence it holds up, and [`rare_event_ips_illustrated.ipynb`](https://github.com/fazlurnu/OpenCDaRR/blob/main/examples/handbook/rare_event_ips_illustrated.ipynb) for a plotted walkthrough of what one run does.

## The interacting particle system

The quantity of interest is a **reach probability**: $\gamma = P(\tau < T)$, the chance that an encounter's separation reaches the rare set $D$ — loss of separation, $\text{sep} < \texttt{rpz}$ — within the horizon $T$, with $\tau$ the first time it does.

Splitting rests on one identity. Nest the rare set in a ladder of shrinking sets $D = D_m \subset \dots \subset D_1$, where $D_k = \{\,\text{sep} \le d_k\,\}$ for shell distances $d_1 > \dots > d_m = \texttt{rpz}$. Reaching $D$ is then a chain of steps, each far more likely than the whole — in the eight-level ladder of Blom et al. (2007, Table 10.8) the per-level fractions run from 0.005 to 0.76 against a product near $10^{-6}$:

$$\gamma = \prod_{k=1}^{m} \gamma_k, \qquad \gamma_k = P(\tau_k < T \mid \tau_{k-1} < T).$$

The estimator realises that product with a fixed population of $N$ particles (Blom et al. 2007, §10.2.4). For each shell $k$:

1. **Mutation** — evolve every particle (`env.advance`) until its running-minimum separation crosses $d_k$ (a *survivor*, frozen at its crossing state) or the encounter ends first (*dropped*).
2. **Selection** — count the survivors; the conditional factor is $\hat p_k = S_k / N$.
3. **Splitting** — resample the $S_k$ survivors with replacement back up to $N$, concentrating effort on the trajectories that got closer.

$$\hat P = \prod_{k=1}^{m} \hat p_k = \prod_{k=1}^{m} \frac{S_k}{N}.$$

The hats are the whole difference. $\gamma_k$ is the true conditional probability, a number the model fixes; $\hat p_k = S_k/N$ is what one run counted, so it moves with the seed — 300 of 1000 particles through a shell reads $0.300$, the next seed might read $0.287$.

The two are tied by an average, $\mathbb{E}[\hat P] = \gamma$ — exactly, provided the simulated process is strong Markov (Cérou et al. 2006, in the Feynman–Kac framework of Del Moral 2004; Blom et al. 2007, Remark 10.1). It is the **product** that is unbiased, not the individual factors: from the second shell on the cloud is resampled survivors, so each $\hat p_k$ is slightly wrong and the factors are correlated, and their errors cancel across the multiplication rather than within it. Any single $\hat P$ is one draw from a right-skewed spread, which is why a run reports an interval from independent replications rather than a bare number.

Because the population is held at $N$ and resampling equalises it at every shell, there are **no per-particle weights** — just a product of survival ratios. A shell with zero survivors **collapses** the run: `ips_once` records $\hat P = 0$ with the level marked, a sign the ladder is too aggressive or $N$ too small, never a valid data point.

IPS targets the identical $P(\text{LoS})$ Monte Carlo does — the initial particles are drawn from the same encounter distribution, splitting acts only on the forward CNS noise, and there is no absorbing kill at CPA, so a particle whose recovery manoeuvre re-approaches stays alive. That is what makes the [validation against Monte Carlo](validation.md) a direct comparison.

!!! note "Splitting reads the running minimum, not the instantaneous separation"
    True separation dips to the closest point of approach and rises again, so a particle would
    cross a shell going in and again coming out. The running minimum only ever decreases, so every
    crossing is one-way and each $\tau_k$ is a genuine first-hitting time — which is why splitting
    reads `FleetState.min_sep`.

## Status and limits

The last shell is $d_m = \texttt{rpz}$, so IPS estimates loss of separation, the same event Monte Carlo does. Pushing $d_m$ down to a physical collision radius ($P \sim 10^{-7}$ and below, out of reach for plain Monte Carlo) is the natural next step on the same machinery.

The ladder is hand-chosen, and that is the main obligation: a shell too far from the last drops the survival fraction to zero and collapses the replication, so keeping each fraction roughly 10–50% is a tuning task. The shells also ladder on `min_sep`, which uses position only and stays flat until the final approach; the look-ahead coordinate of Blom et al. (2007, eq. 10.7) discriminates earlier. The planned upgrade is **adaptive multilevel splitting** (Cérou & Guyader 2007), choosing each shell as a quantile of the current cloud instead of fixing it in advance, which removes both the guesswork and the collapse risk. Every run stays reproducible: `config + seed + code-hash → (P, CI)`.
